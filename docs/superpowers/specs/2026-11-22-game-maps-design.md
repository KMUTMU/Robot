# 주행 게임 개편 설계: 실물 차 반영 + 맵 6개 (2026-11-22)

> 요청(11-22): "이걸로 업데이트해줘. 자동차 모델링해서 게임에 업데이트. 학습하면서 찍었던 사진 바탕으로 공간 재현. 그 외에도 다양한 공간 여러 개. 재밌게"
> 사용자가 맵 구성은 맡김("재밌게") → 아래 맵 구성은 **에이전트 제안**이고, 채팅으로 먼저 알린 뒤 답이 없어 그대로 진행함. 바꾸고 싶으면 맵 단위로 빼거나 고칠 수 있게 맵마다 파일을 나눔.

## 1. 왜 하는가
- 차가 달라졌음: 보조배터리를 실은 뒤 사진 9장(`차사진_20261122/`)이 새 기준. 3D 분해도와 게임 속 차가 예전 배치(보조배터리 "장착 예정")로 남아 있음.
- 실제로 데이터를 모은 공간(11-21 저녁, 8,285장)을 게임에서 다시 달려 보고 싶음. 실차가 못 도는 코너를 화면에서 다시 보는 용도도 됨.
- 게임은 집 맵 하나뿐이라 금방 질림 → 성격이 다른 공간을 여러 개.

## 2. 목표 / 하지 않는 것
**목표**
1. 3D 분해도와 게임 속 차가 11-22 사진과 같은 배치.
2. 맵 선택 화면. 맵 6개: 집(기존), 수집한 거실, 거인의 책상, 달 기지, 볼링장, 얼음 호수.
3. 모든 맵에서 기존 기능(녹화 20Hz, 체크포인트·랩, AI 데모, 미니맵, 차 카메라, 터치, 게임패드)이 그대로 동작.
4. 맵마다 다른 재미: 점프(달), 미끄러짐(얼음), 떨어짐(책상), 핀 쓰러뜨리기(볼링), 실차 감각(거실).

**하지 않는 것**: 거실의 mm 단위 정확도(사진이 160×120 광각이라 눈대중), 실제 차량 동역학 수준의 물리, 기록 저장·온라인 기능.

**이러면 실패**: 기존 집 맵의 주행감·랩이 달라짐 / 노트북에서 눈에 띄게 느려짐 / 한 파일 HTML이 지나치게 커짐(목표 1.5MB 이하) / 맵을 바꿀 때 오류.

## 3. 조사한 것
### 차 사진 (11-22)
- 짐칸: 맨 뒤에 **보조배터리**(검정, 금색 테두리 버튼, 가로로 눕혀 뒤쪽이 들린 채 약 20° 기울어짐, 내장 케이블이 뒤로 고리를 그리며 Pi USB-C로) → **Pi 5**(긴 변이 좌우, USB·랜 단자가 차 오른쪽, USB-C 쪽이 뒤) → **PCA9685**(Pi 앞, 긴 변이 좌우). I2C 점퍼선 4가닥(갈·빨·주·노 리본)이 Pi 위로 큰 고리.
- 가운데: 구동 배터리가 **연두색** 원통(모델은 파랑), ESC·UBEC·단자대는 기존 모델과 같은 자리.
- 앞: 검은 판 위 **투명 원통 2개**(금색 캡)가 앞으로 약 15° 숙여져 있고 벨크로 + 글루건. 카메라와 FPC 경로는 기존 모델과 같음.
- 기존 모델의 섀시·바퀴·치수는 옆 사진과 맞음(휠베이스 190mm 기준 뒤끝 0, 짐칸 앞 156, 앞 판 끝 약 318) → 차체는 그대로 두고 **위 4가지만 고침**.

### 수집 데이터 (11-21)
- 오른쪽으로 도는 한 바퀴 ≈ 300장(15초), 스로틀 1.0. 조향·스로틀 기록을 적분하면 **모서리가 둥근 네모**(가로 4.6 : 세로 4.4, 둘레 15, 단위는 "최고 속도로 1초 간 거리").
- **측정값**: 최대 조향 + 스로틀 1.0에서 초당 0.80 rad(약 46°) 회전. **추정값**: 속도 약 0.8 m/s → 최소 회전 반지름 약 1.0 m, 코스 약 3.6 × 3.5 m, 둘레 약 12 m. (속도를 잰 적이 없어 크기는 가구 크기와 맞춰 잡은 값)
- 보이는 것: 북쪽 벽에 흰 TV장(다리, 위에 큰 TV, 서쪽 끝에 화분과 흰 기둥, 동쪽 끝 바닥에 노란 장난감), 서쪽 벽은 베이지 패널 + 낮은 갈색 장, 남서쪽 밖에 실내 자전거(매트, 빨간 운동화)와 옷걸이, 남쪽은 밝고 멀리 원목 문, 남동쪽에 침대와 선풍기, 동쪽 벽에 낮은 갈색 장. 코스 안쪽에 낮은 갈색 탁자(노트북·모니터)와 남색 좌식 의자 4개, 서쪽 의자에 사람. 북쪽 절반은 불이 꺼져 어둡고 남쪽은 다운라이트. 바닥은 밝은 원목 마루, 카메라는 가장자리가 자홍색.

### 게임 코드
- `game/src/game.js` 한 파일(1,866줄)에 집 배치·경로·미니맵·로봇청소기·고양이가 전역으로 고정. 물리는 평면 자전거 모델(턱 24mm 제한, 떨어지면 즉시 바닥 높이로), 미끄러짐·공중 없음.

## 4. 접근 방법
| 방법 | 내용 | 평가 |
|---|---|---|
| A. 페이지 안에서 맵 교체 (채택) | 맵을 모듈로 나누고 `loadMap(id)`이 세계(정적 메시·충돌체·경로·소품·움직이는 것·조명·미니맵)를 통째로 갈아 끼움 | 아티팩트·파일 어디서나 동작, 시작 화면 뒤에서 맵을 바로 미리 봄. 정리(dispose) 코드가 필요 |
| B. 주소로 맵 선택 후 새로 고침 | `?map=moon`으로 다시 로드 | 구현은 쉽지만 claude.ai 아티팩트 안에서 주소 변경·새로 고침이 막힐 수 있음 |
| C. 맵마다 HTML 파일 | 파일 6개 | three.js 0.9MB가 6번 중복, 아티팩트도 6개 → 관리 불가 |

## 5. 구조
```
game/src/core.js        렌더러, 공용 텍스처·재질, 세계 도우미(box·cyl·plane·addBox·addCircle·groundH), 메시 합치기
game/src/maps/house.js  기존 집 (코드 이동, 내용 그대로)
game/src/maps/living.js 수집한 거실
game/src/maps/desk.js   거인의 책상
game/src/maps/moon.js   달 기지
game/src/maps/bowling.js 볼링장
game/src/maps/ice.js    얼음 호수
game/src/main.js        차, 소품, 움직이는 것, 물리, 경로·체크포인트, UI, 루프, loadMap
game/build.py           core → maps → main 순서로 이어 붙임 (/*CAR*/는 지금처럼 3d_model에서)
```
맵 정의: `MAPS.push({ id, name, tag, lede, collect, free, toastStart, env, phys, bounds, route:{wp,cp,tapeHalf}, labels, build(), hooks })`.
- `build()`는 지금의 `buildHouse()`처럼 도우미를 불러 세계를 채움. 지형이 있는 맵은 높이 격자(`setTerrain(fn, cell)`)를 주고, 물리와 그림이 같은 격자를 써서 어긋나지 않게 함.
- `env`: 배경, 안개, 반구광, 주광(방향·색·세기), 보조광, 노출 → 맵을 바꿀 때 적용. 점광원은 맵이 `dyn` 그룹에 직접 추가.
- `phys`: `g`(중력), `aLat`(옆 방향 버티는 가속도), `aLong`(가감속 한계), `vmax`, `dmax`(최대 조향각), `bounce`, `killY`.
- `hooks`: `step(dt)`, `sync(dt)`, `onLand(초, 거리)`, `hud()`(도전 표시 문구), `reset()`.
- 소품 종류 추가: 볼링핀(쓰러짐), 볼링공, 퍽, 지우개·주사위, 운동화·장난감, 눈덩이. 움직이는 것은 공통 인터페이스(`step/sync/reset/onHit`)로 바꾸고 로봇청소기·고양이·펭귄이 구현.

## 6. 물리 추가 (기본값이면 기존과 같아야 함)
1. **공중**: `car.py`(높이), `car.vy`. 땅이 중력보다 빨리 꺼지면(경사 끝, 책상 끝) 뜨고, 뜬 동안은 조향·가감속이 안 먹고 속도를 유지, 착지하면 충격음과 약한 튐. 뜬 높이보다 낮은 턱·충돌체(`top` 지정)는 넘어감. `py < killY`면 떨어진 것으로 보고 되돌림.
2. **미끄러짐**: 차 기준 옆 속도 `vl`. 회전하면 생기는 옆 속도를 매 스텝 `aLat·dt`만큼만 없앰. 기본 `aLat = 9810`이면 지금 속도 범위에서 항상 다 없어져 기존과 같음. 얼음은 650 정도라 미끄러지며 돎. 가감속도 `aLong`으로 제한(헛바퀴).
3. **차 세팅**: 맵별 `vmax`, `dmax`. 거실은 수집 기록에 맞춰 `vmax 800mm/s`, `dmax 10.8°`(최소 회전 반지름 1.0m), 시작 최대 스로틀 1.0.

## 8. 화면
- 시작 화면 왼쪽 위에 맵 카드 6개(가로 스크롤, 키보드 1~6, 게임패드 LB/RB). 고르면 뒤 배경이 그 맵으로 바뀌고 제목·설명·모드 설명이 맵에 맞게 바뀜.
- HUD 오른쪽 패널에 "도전" 한 줄(맵에 도전이 있을 때만). 미니맵은 맵 범위에 맞춰 자동 축척.
- 문구는 맵마다 따로(시작 안내, 자유 주행 안내).

## 9. 3D 차 모델 변경 (3d_model/src/app.js)
- `powerbank`: 실제 배치(검정, 기울어짐, 버튼·LED, 뒤로 고리를 그리는 케이블과 USB-C 플러그), "장착 예정" 표시와 토글 제거.
- `battery`: 연두색. `cammount`: 원통 2개를 15° 숙이고 글루건 자국. `i2c`: 큰 고리의 4색 리본. 설명 문구(DEFS) 갱신.
- 게임은 같은 코드를 잘라 쓰므로 다시 빌드하면 반영.

## 10. 확인 방법
- 개편 전 게임을 기준으로, 집 맵 AI 한 바퀴 시간과 충돌 수가 같은지(±2%).
- 맵마다: 콘솔 오류 없음, AI 데모가 한 바퀴를 충돌 없이 완주, 추격·차 카메라·위에서 본 화면 캡처를 눈으로 확인.
- 물리: 달에서 점프대 체공 0.5초 이상, 책상 끝에서 떨어지면 되돌림, 얼음에서 옆 속도가 생김, 볼링 핀이 쓰러지고 다시 섬, 펭귄이 피함.
- 모바일 가로 화면에서 시작 화면과 맵 카드가 겹치지 않는지.
- 확인 못 하는 것: 실제 GPU 성능, 게임패드, 소리 (헤드리스 환경) → 문서에 미확인으로 적음.

## 11. 에이전트가 정한 것 (사용자 확인 없이)
- 맵 5개의 주제와 도전 요소, 거실의 방 크기·가구 치수, 실차 속도 0.8 m/s 가정.
- 거실 맵에 사람 모형(얼굴 없는 단순 모형)을 넣음: 수집 사진마다 찍혀 있어서.
- 설계·계획 문서 위치 `docs/superpowers/`.
